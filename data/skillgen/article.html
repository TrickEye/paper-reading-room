摘要Abstract

技能是一种很有前景的方式，可以在不重新训练的情况下提升大语言模型智能体的能力，同时使新增流程保持可复用、可控。然而，高质量技能目前仍主要由人工编写。我们提出 SkillGen：一种多智能体框架，从基础智能体生成的轨迹中合成单个可审计技能。输出是人类可读的产物，可在使用前检查。SkillGen 并非仅仅概括轨迹，而是对成功与失败轨迹进行对比归纳，以识别可复用的成功模式、反复出现的失败模式，以及相近成功案例中出现、但失败案例中缺失的行为。随后，SkillGen 生成候选技能并迭代改进。其关键创新是将智能体技能建模为干预，以实证验证技能对整体性能的净影响。具体来说，我们在相同实例上比较使用和不使用技能的结果，同时考虑修复（技能纠正基线失败的情况）与退化（技能破坏基线成功的情况）。在广泛的智能体和数据集上，SkillGen 持续提升留出集性能，优于现有技能生成基线，并生成可跨模型迁移的技能。Skills are a promising way to improve LLM agent capabilities without retraining, while keeping the added procedure reusable and controllable. However, high-quality skills are still largely written by hand. We introduce SkillGen, a multi-agent framework that synthesizes a single auditable skill from trajectories generated by a base agent. The output is a human-readable artifact that can be inspected before use. Rather than merely summarizing trajectories, SkillGen leverages contrastive induction over both successful and failed trajectories to identify reusable success patterns, recurring failure modes, and behaviors that appear in nearby successes but are missing from failures. SkillGen then generates candidate skills and iteratively refines the skill. A key novelty in SkillGen is that we model agent skills as interventions to empirically verify the net effect of skills on the overall performance. Specifically, we compare outcomes on the same instances with and without the skill, so that we account for both repairs (cases where the skill fixes a baseline failure) and regressions (cases where the skill breaks a baseline success). Across a broad range of agents and datasets, SkillGen consistently improves held-out performance, outperforms existing skill-generation baselines, and produces skills that transfer across models.

1 引言1 Introduction

大语言模型（LLM）越来越多地用于解决复杂的多步骤任务（Schick et al., 2023；Qin et al., 2024；Yao et al., 2023；Wang et al., 2023a）。形式化这类行为的一种常见方式是技能：在不修改模型权重的前提下，以可复用的推理时流程编码任务特定指导，例如指令、可执行代码和领域知识（Zhang et al., 2025；Anthropic, 2025）。技能具有模块性且可审计：由于它们是可读的推理时产物，而不是权重更新或提示词搜索，人们可以检查其编码的流程，直接修改，并在部署前测试其效果。但在实践中，高质量技能仍主要靠人工编写。Large language models (LLMs) are increasingly used to solve complex, multi-step tasks (Schick et al., 2023; Qin et al., 2024; Yao et al., 2023; Wang et al., 2023a). A common way to formalize such behavior is through skills: reusable, inference-time procedures that encode task-specific guidance, such as instructions, executable code, and domain knowledge, without modifying model weights (Zhang et al., 2025; Anthropic, 2025). Skills are modular and auditable: because they are readable inference-time artifacts rather than weight updates or prompt searches, one can inspect the procedure they encode, revise it directly, and test its effect before deployment. In practice, however, high-quality skills are still largely hand-written.

自动技能合成旨在从智能体经验中学习可复用技能（Shinn et al., 2023；Zhao et al., 2024；Ni et al., 2026；Alzubi et al., 2026；Wang et al., 2026a；Zhang et al., 2026）。然而，现有方法有两个关键缺陷。第一，现有方法主要从成功轨迹中学习，即使考虑失败，通常也只是独立概括，而不与同一任务中的相近成功案例进行对比。因此，已有工作遗漏了成功与失败之间的关键对比信号——即智能体在相似上下文中正确执行了什么，又在失败执行中遗漏了什么。例如，成功轨迹可能包含失败尝试中缺失的中间验证步骤，但只从成功中学习无法单独识别这一中间验证的重要性，也就不会将其归纳为可复用模式。第二，现有方法不显式验证生成技能的实证收益。技能可能修复部分失败，却也可能在智能体此前正确解决的案例上引入新的失败模式。因此，技能合成本质上是一个干预问题，需要比较使用与不使用候选技能时对智能体性能的净影响。这种性能评估也是最终建立有原则的候选技能迭代改进方法所必需的。Automated skill synthesis aims to learn reusable skills from agent experience (Shinn et al., 2023; Zhao et al., 2024; Ni et al., 2026; Alzubi et al., 2026; Wang et al., 2026a; Zhang et al., 2026). However, existing methods have two key shortcomings. First, existing methods primarily learn from successful trajectories, and even when failures are considered, they are typically summarized in isolation rather than contrasted against nearby successes on the same task. As a result, prior work misses a key contrastive signal between success and failure—that is, what the agent executes correctly in similar contexts and what it omits in failed roll-outs. For example, a successful trajectory may include an intermediate validation step that is absent in a failed attempt, but success-only learning does not isolate that such intermediate validation is important and would not put into a reusable pattern. Second, existing methods do not explicitly verify the empirical benefit of a generated skill. While a skill may repair some failures, it can also introduce new failure modes on cases that the agent previously solved correctly. As a result, skill synthesis is fundamentally an interventional problem, where one compares the net-effect on the agent’s performance with and without the candidate skill. Also, such performance evaluation is necessary to eventually build iterative approaches to refine candidate skills in a principled manner.

我们提出 SkillGen：一种自动进行推理时技能合成的多智能体框架（见图 1）。SkillGen 以已有的 LLM 轨迹数据集为输入，推导出单个可审计技能：这是一种可读干预，其任务上下文、成功流程和失败教训均可检查，其实证净效果在部署前得到验证。输入数据集可以在基线采集阶段收集，汇集成功和失败轨迹。框架通过三个专门的智能体运行：（1）对比归纳智能体分析输入轨迹，提取可复用成功模式并识别反复出现的失败模式，以呈现成功与失败执行间的差异，从而输出包含任务诊断的紧凑、可解释摘要。（2）在生成—验证—改进循环中，将诊断转为候选技能，再利用反馈迭代改进技能（使用生成智能体和验证智能体）。最终技能通过衡量对最终留出集性能的净影响来选择。这确保选出的技能改善整体性能，同时考虑“修复”（技能纠正失败）和“退化”（技能破坏正确案例）。据我们所知，SkillGen 是首个将推理时技能合成建模为干预问题，以确保对性能具有经实证验证的正向影响的智能体框架。We introduce SkillGen: a multi-agent framework for automatic, inference-time skill synthesis (see Fig. 1). SkillGen takes an existing dataset of LLM trajectories as input and derives a single auditable skill: a readable intervention whose task context, success procedures, and failure lessons can be inspected and whose empirical net effect is verified before deployment. The input dataset can be collected during a baseline elicitation phase to compile successful and failed trajectories. Our framework operates through three specialized agents: (1) A contrastive induction agent analyzes the input trajectories to extract reusable success patterns and identify recurring failure modes, with the aim to surface contrasts between successful vs. failed roll-outs. (2) In a generation-verification-refinement loop, the diagnostics are converted into candidate skills, and the skills are then iteratively refined based on feedback (using a generation agent and a verification agent. This ensures that the selected skill improves the overall performance and thus accounts for “repairs” (i.e, when a skill fixes a failure) and “regressions” (i.e., when a skill breaks a correct case). To the best of our knowledge, SkillGen is the first agentic framework that models inference-time skill synthesis as an intervention problem to ensure a positive, empirically verified effect on performance.

2 预备知识2 Preliminaries

我们将推理时技能视为改变基础智能体行为、进而改变其任务性能的干预。这一视角自然引出在相同输入上比较使用与不使用给定技能时的结果。We view inference-time skills as interventions that modify the behavior of a base agent and thereby change its task performance. This perspective naturally induces a comparison between outcomes with and without a given skill on the same inputs.

技能干预：我们将候选技能定义为推理时干预 s=(u,a,𝒫,ℛ)，其中 u 是结构化提示词，a 是任务元数据（如任务描述），𝒫 是可选的可执行脚本集合，ℛ 是可选的辅助文档集合。这些组成部分共同定义 SkillGen 所考虑的技能空间。Skill interventions: We define a candidate skill as a inference-time intervention s=(u,a,𝒫,ℛ), where u is a structured prompt, a is task metadata (e.g., task description), 𝒫 is an optional set of executable scripts, and ℛ is an optional collection of auxiliary documents. 我们将技能建模为改变智能体行为、进而改变其结果的干预。为比较评估技能学习，我们采用潜在结果框架（Rubin, 2005），以有原则的方式形式化处理效应。对任意输入 x 和候选技能 s，我们定义两个潜在结果：基线结果（即 Y0​(x)=Y⁡(x,τ0​(x))）和技能增强结果（即 Ys​(x)=Y⁡(x,τs​(x))，τs(x)∼P𝒜(⋅∣x;η(s))）。加载技能 s 对应于向 𝒜 施加干预 η⁡(s)。We model skills as interventions that change the agent’s behavior and thus its outcomes. To make comparative assessments of skill learning, we adopt the potential outcome framework (Rubin, 2005) as a principled manner to formalize the treatment effects. For any input x and a candidate skill s, we define two potential outcomes: the baseline outcome (i.e., Y0​(x)=Y⁡(x,τ0​(x))) and the skill-augmented outcome (i.e., Ys​(x)=Y⁡(x,τs​(x)), τs(x)∼P𝒜(⋅∣x;η(s)). Loading a skill s corresponds to applying an intervention η⁡(s) into 𝒜.

因此，Δ⁡(s) 刻画技能干预 s 引起的净效果：它衡量技能在相同输入分布上使性能改善（或恶化）的程度，同时考虑“修复”（技能纠正基线失败）和“退化”（技能破坏基线成功）。因此，技能合成的目标是在不依赖人工编写任务特定技能的情况下，选择对留出集性能具有正向净影响的技能。在构建期间，每个候选技能都在 𝒟ver 上、针对相同输入比较使用和不使用技能的情况。由此得到所谓状态 σver​(s,𝒟ver)∈{active,deprecated}。部署时只加载 active（启用）技能；deprecated（弃用）技能归入空干预 ∅。Thus, Δ⁡(s) captures the net-effect induced by a skill intervention s: it measures how much the skill improves (or degrades) performance on the same input distribution, while accounting for both “repairs” (i.e., cases where the skill fixes a baseline failure) and “regressions” (i.e., cases where the skill breaks a baseline success). The objective for skill synthesis is therefore to select a skill with positive net-effect on held-out performance, but without relying on human-written task-specific skills. During construction, each candidate skill is evaluated on 𝒟ver under identical inputs with and without the skill. As a result, we yield a so-called status σver​(s,𝒟ver)∈{active,deprecated}. 3 SkillGen3 SkillGen

概览。SkillGen 的输入包括：基础智能体、一组观测到的 LLM 轨迹（划分为归纳子集和验证子集），以及任务级评估器。随后返回单个可审计技能。SkillGen 采用三个阶段的智能体框架（见图 1；伪代码见附录 A 的算法 1）。阶段 1，基线采集：使用基础智能体收集成功与失败轨迹。阶段 2，对比归纳：提取反复出现的失败模式，识别区分成功与失败执行的局部模式，并由归纳智能体将其组合为紧凑、可解释的任务级诊断摘要。阶段 3，迭代生成—验证—改进循环：通过生成智能体将诊断转为候选技能，通过验证智能体在验证子集上测试每个候选技能的性能，最后改进候选技能。最终返回构建期净效果 Δ⁡(s) 最大的候选技能。Overview. SkillGen takes as input: a base agent, a set of observed LLM trajectories (split into an induction subset and verification subset), and a task-level evaluator. SkillGen then returns a single auditable skill. SkillGen follows an agentic, three-staged framework (see Fig. 1; pseudocode in Alg. 1 in Appendix A). Stage  baseline elicitation: this stage uses the base agent to collect successful vs. failed trajectories. Stage  contrastive induction: this stage extracts recurring failure modes to identify local patterns that distinguish successful vs. failed roll-outs; the patterns are combined into a compact, interpretable summary of task-level diagnostics (via the induction agent). Stage  an iterative generation–verification–refinement loop: this stage turns the diagnostics into candidate skills (via the generation agent), tests each candidate skill on the verification subset for performance evaluation (via the verification agent), and finally makes refinements to the candidate skill. Finally, the candidate skill with the largest construction-time net-effect Δ⁡(s) is returned.

首先在归纳子集上运行基础智能体并存储：We first run the base agent on the induction subset and store

这里，ℐ− 索引失败的基线执行，ℐ+ 索引成功执行。直观而言，失败揭示基础智能体需要帮助的地方；成功揭示其已经能够执行的流程。同时利用这两类数据是 SkillGen 的独特之处，且非常重要：仅使用失败可能产生误导或无益的建议，而仅使用成功则无法识别能力缺口。Here, ℐ− indexes failed baseline rollouts and ℐ+ indexes successful ones. Intuitively, failures show where the base agent would need help; and successes show procedures the base agent can already execute. Using both strata is unique to SkillGen and important: failures alone can produce misleading or unhelpful advice, while successes alone do not identify the capability gap.

ℬver={(x~j,τ~j0,bj)}j=1m,τ~j0∼P𝒜(⋅∣x~j;∅),bj=Y(x~j,τ~j0).

缓存结果既不供归纳智能体使用，也不供第一轮生成智能体使用；而是在后续用于构建期验证和随后的改进。主要动机是，之后可以在相同验证子集上将每个候选技能与无技能智能体的行为进行比较。The cached outcomes are neither used by the induction agent nor the first-round generation agent; instead, the cached outcomes are later used for construction-time verification and subsequent refinement. The main motivation is that we can later compare each candidate’s skill against the behavior of the no-skill agent on the same verification subset.

我们复用一个源模型的最终 SkillGen 技能而不重新训练，再在 ALFWorld OOD、ScienceWorld、Mind2Web 和 SocialMaze FTS 上由另一个评估模型执行，以评估迁移。每个迁移技能均与评估模型自己的无技能基线比较；被源流水线标记为“deprecated”的技能保留为空操作技能。图 4 表明 SkillGen 生成的技能经常能够跨模型迁移，但技能生成模型的选择很重要。在 120 个非对角比较中，70% 为非负，42% 超过 +5 个百分点。存在一个清晰规律：可迁移技能并不总由最强的基线智能体编写；在 ALFWorld 上，Qwen-2.5-7B 是平均表现最好的技能生成模型，而在 ScienceWorld 上，GPT-5.4-Nano 最好。We evaluate transfer by reusing the final SkillGen skill from one source model without retraining it, then executing it with a different evaluator model on ALFWorld OOD, ScienceWorld, Mind2Web, and SocialMaze FTS. Each transferred skill is compared against the evaluator’s own no-skill baseline; skills marked ‘deprecated’ by the source pipeline are retained as no-op skills. Figure 4 shows that SkillGen produces skills that often transfer across models, but relevant is the choice of skill-generating model. Across 120 off-diagonal comparisons, 70% are non-negative, and 42% exceed +5 pp. We see a clear pattern: transferable skills are not simply written by the strongest baseline agents; on ALFWorld, Qwen-2.5-7B is the best skill-generating model on average, while, on ScienceWorld, GPT-5.4-Nano is best.

SkillGen 在哪些其他任务场景中也能提供有用增益？In which additional task regimes does SkillGen provide useful gains?

图 5 评估 τ-Bench 上的长程零售工具使用。对于技能通过验证门控的每个模型，SkillGen 均提升性能，平均增益为 +5.3 个百分点；候选技能未通过门控的模型保持不变，不施加未经验证的干预。Figure 5 evaluates long-horizon retail tool use on τ-Bench. SkillGen improves every model whose skill passes the verification gate, with an average gain of +5.3 pp; models whose candidates fail the verification gate are left unchanged rather than exposed to an unverified intervention.

图 6 评估 ChemLLMBench 上由脚本和参考资料增强的技能。其中，产率预测受益，在六个模型上平均提升 +16.1 个百分点；性质预测则更受知识约束，仅少部分智能体有所改善。综合而言，这些结果说明，当任务能够通过流程学习，而非主要依赖领域事实回忆时，资源包技能尤为有用。Figure 6 evaluates script- and reference-augmented skills on ChemLLMBench. Here, yield prediction benefits, with an average improvement of +16.1 pp across six models, while property prediction is more knowledge-bound and improves only for a small subset of agents. Together, these results suggest that resource-bundle skills are especially useful when the task is procedurally learnable, rather than being primarily a matter of recalling domain facts.

为什么选择经验证表现最好的改进轮次，而不是最新候选技能？Why select the best verified refinement round instead of using the latest candidate?

图 7 为将改进视为 K 选优搜索、而非采用最新候选技能提供实证依据。每轮候选技能存在噪声：到第 8 轮，最新候选技能的期望 Δ=−3.1 个百分点，而经验证的最佳候选技能达到 +8.1 个百分点（差距约 11 个百分点）。因此，验证门控不仅是保障检查，也是将不稳定改进轨迹转化为可靠最终技能的选择机制。Figure 7 provides an empirical justification for treating refinement as best-of-K search rather than using the latest candidate. Per-round candidates are noisy: by round 8, the latest candidate has expected Δ=−3.1 pp, while the best verified candidate reaches +8.1 pp (i.e. a gap of ∼ 11 pp). Thus, the verification gate is not just a safety check; it is also the selection mechanism that turns unstable refinement trajectories into a reliable final skill.

生成技能揭示了哪些定性失败模式与启示？What qualitative failure modes and insights emerge from the generated skills?

我们还检查人工记录的基准摘要和各模型技能分析报告；详细定性分析见附录 C.9。分析支持三个要点：（i）验证门控移除了许多有害候选技能，但被接受的技能在留出实例上仍可能过度泛化；（ii）交互环境中的残余失败通常是流程执行不完整，而非单个局部动作错误；（iii）化学和编程失败经常反映任务落地或全局结构方面的局限，可复用推理时技能并不总能修复。这些观察与 SkillGen 的设计一致：对比学习的诊断摘要识别反复出现的流程缺口，而构建期验证限制有害技能干预的部署。We also inspect manually logged benchmark summaries and per-model skill-analysis reports; a detailed qualitative analysis is in Appendix C.9. Our analysis supports three takeaways: (i) the verification gate removes many harmful candidate skills, although accepted skills can still overgeneralize on held-out instances; (ii) residual failures in interactive environments are usually incomplete procedure execution rather than single local action mistakes; and (iii) chemistry and coding failures often reflect grounding or global-structure limits that a reusable inference-time skill cannot always repair. These observations align with the design of SkillGen: summary diagnostics for contrastive learning identify recurring procedural gaps, while construction-time verification limits the deployment of harmful skill interventions.

智能体技能。早期 LLM 智能体通过外部工具使用［Schick et al., 2023；Qin et al., 2024］或工具创建［Qian et al., 2023］增强模型；而 ReAct［Yao et al., 2023］、Reflexion［Shinn et al., 2023］、ExpeL［Zhao et al., 2024］和 Voyager［Wang et al., 2023a］等交互型智能体则表明，轨迹可以支持可复用的推理与行动惯例。Agent skills. 智能体技能提供一等抽象，通常遵循 Anthropic Agent Skills 标准［Zhang et al., 2025；Anthropic, 2025］；该标准将技能定义为在推理时动态加载、可组合的指令、脚本与资源包。近期综述系统梳理了技能架构、获取、安全与部署［Xu and Yan, 2026；Jiang et al., 2026］。在构建方面，Trace2Skill［Ni et al., 2026］、EvoSkill［Alzubi et al., 2026］、EvoSkills［Zhang et al., 2026］和 SkillX［Wang et al., 2026a］从智能体经验中合成技能；SkillWeaver［Zheng et al., 2025］、WebXSkill［Wang et al., 2026b］、AutoSkill［Yang et al., 2026］和 SkillRL［Xia et al., 2026］则研究网页、对话与强化学习部署场景。SkillGen 的不同之处在于以失败分析为核心：聚类错误模式、识别能力边界，并通过多智能体协作验证归纳技能，以配对修复与退化为依据制定构建期部署规则。Agent skills provide a first-class abstraction that often follows the Anthropic Agent Skills standard [Zhang et al., 2025, Anthropic, 2025], which defines skills as composable bundles of instructions, scripts, and resources loaded dynamically at inference time. Recent surveys systematize skill architecture, acquisition, security, and deployment [Xu and Yan, 2026, Jiang et al., 2026]. On the construction side, Trace2Skill [Ni et al., 2026], EvoSkill [Alzubi et al., 2026], EvoSkills [Zhang et al., 2026], and SkillX [Wang et al., 2026a] synthesize skills from agent experience, while SkillWeaver [Zheng et al., 2025], WebXSkill [Wang et al., 2026b], AutoSkill [Yang et al., 2026], and SkillRL [Xia et al., 2026] study web, dialogue, and RL deployment regimes. SkillGen differs by making failure analysis central: it clusters error patterns, identifies capability boundaries, and verifies induced skills through multi-agent collaboration with a construction-time deployment rule over paired repairs and regressions.

LLM 智能体的合成数据。Self-Instruct［Wang et al., 2023b］发展了由 LLM 自举的指令生成，启发了 Alpaca［Taori et al., 2023］、WizardLM［Xu et al., 2024］等后续扩展，以及通过推理轨迹、数据整理、合成教科书和分类体系驱动生成进一步改善质量的工作［Mukherjee et al., 2023；Zhou et al., 2023；Gunasekar et al., 2023；Li et al., 2024］。近期流水线通过智能体流程或自合成［Mitra et al., 2024；Xu et al., 2025］、可控生成与验证［Huang et al., 2025c］、领域特定且感知工具的构建［Huang et al., 2025b］、经验证的视觉问答［Bao et al., 2024］和注入风险的安全轨迹［Huang et al., 2025a］扩大合成数据规模。Synthetic data for LLM agents. Self-Instruct [Wang et al., 2023b] developed LLM-bootstrapped instruction generation, which inspiring later extension such as Alpaca [Taori et al., 2023], WizardLM [Xu et al., 2024], and further quality improvements through reasoning traces, curation, synthetic textbooks, and taxonomy-driven generation [Mukherjee et al., 2023, Zhou et al., 2023, Gunasekar et al., 2023, Li et al., 2024]. Recent pipelines scale synthetic data with agentic flows or self-synthesis [Mitra et al., 2024, Xu et al., 2025], controllable generation and verification [Huang et al., 2025c], domain-specific tool-aware construction [Huang et al., 2025b], verified visual question answering [Bao et al., 2024] and risk-injected safety trajectories [Huang et al., 2025a].

针对智能体特定能力，AgentTuning［Zeng et al., 2024］、Agent-FLAN［Chen et al., 2024］、FireAct［Chen et al., 2023］和 Instruct-SkillMix［Kaur et al., 2025］构建用于指令调优的轨迹或技能组合数据。这些方法产出模型微调数据；SkillGen 则合成无需更新参数即可加载的结构化推理时技能包，以解决系统性失败分析揭示的能力缺口。For agent-specific capabilities, AgentTuning [Zeng et al., 2024], Agent-FLAN [Chen et al., 2024], FireAct [Chen et al., 2023], and Instruct-SkillMix [Kaur et al., 2025] construct trajectory or skill-composition data for instruction tuning. These methods produce data for model fine-tuning; in contrast, SkillGen synthesizes inference-time skills—structured bundles loaded without parameter updates—that target capability gaps exposed by systematic failure analysis.

Trace2Skill。Trace2Skill.

对于 Trace2Skill［Ni et al., 2026］，我们在训练池上进行一次无技能执行。成功分支与错误分支分析器并行处理轨迹，其提出的补丁通过分层 LLM 合并进行整合。我们保留原始提示词结构，除共享 Markdown 技能封装外，不施加额外输出模式。For Trace2Skill [Ni et al., 2026], we run one no-skill rollout over the training pool. Success-branch and error-branch analysts process trajectories in parallel, and their proposed patches are consolidated through hierarchical LLM merging. We preserve the original prompt structure and do not impose an additional output schema beyond the shared Markdown skill wrapper.

SkillX。SkillX.

对于 SkillX［Wang et al., 2026a］，我们进行两轮改进。每轮运行当前技能库，从成功轨迹提取技能卡，使用 text-embedding-3-small、以 0.80 的余弦相似度阈值聚类技能卡，再由 LLM 合并簇，并以 3/5 的 LLM 质量评分阈值筛选技能卡。保留的技能库最多含 12 张卡，随后规范化为最终技能。For SkillX [Wang et al., 2026a], we run two refinement rounds. Each round rolls out the current library, extracts skill cards from successful trajectories, clusters cards by cosine similarity at threshold 0.80 using text-embedding-3-small, merges clusters with an LLM, and filters cards with an LLM quality score threshold of 3/5. The retained library is capped at 12 cards before being canonicalized into the final skill.

EvoSkill。EvoSkill.

对于 EvoSkill［Alzubi et al., 2026］，我们维护 k=3 个候选程序组成的前沿，迭代四次。提议器根据固定验证子集上的失败，在 add_new、edit 和 keep 操作中选择；构建器输出下一候选技能库。只有新候选技能在相同验证子集上优于前沿中最弱成员时才准入。For EvoSkill [Alzubi et al., 2026], we maintain a frontier of k=3 candidate programs for four iterations. A proposer chooses among add_new, edit, and keep operations based on failures from a fixed validation subset, and a builder emits the next candidate library. Admission requires the new candidate to outperform the weakest frontier member on the same validation subset.

CoEvoSkills。CoEvoSkills.

我们从 EvoSkills［Zhang et al., 2026］实例化协同演化基线，使用信息隔离的代理验证器。该代理编写二元自然语言断言，依据断言判断执行，并向技能生成器返回结构化诊断。为匹配其他基线的执行预算，我们采用三次外层迭代和两次内层验证器迭代。由于共享评估接口接收 Markdown 格式技能，而非可执行的多文件包，代理断言由 LLM 判断，不作为代码执行。We instantiate the co-evolutionary baseline from EvoSkills [Zhang et al., 2026] using an information-isolated surrogate verifier. The surrogate writes binary natural-language assertions, judges rollouts against those assertions, and returns structured diagnostics to the skill generator. To match the rollout budget of the other baselines, we use three outer iterations and two inner verifier iterations. Because the shared evaluation interface consumes Markdown-formatted skills rather than executable multi-file bundles, the surrogate assertions are LLM-judged rather than executed as code.

基线比较的范围。Scope of the baseline comparison.

基线比较在本文研究的相同部署问题下评估所有方法：为每个基准—模型对合成一个固定、可审计的推理时技能，并在留出实例上评估这一固定干预。这要求将 SkillX 和 EvoSkill 等原生构建多技能库或从其中检索的方法，适配为与 SkillGen 相同的单技能接口。我们强调，这种受控适配并非旨在衡量这些系统在所有可能的技能库规模、检索策略或路由策略下的完整原生部署潜力，而是在部署产物必须是一个固定技能时，支持对技能合成质量进行同等条件比较。Our baseline comparison evaluates all methods under the same deployment problem studied in this paper: synthesize one fixed, auditable inference-time skill for each benchmark–model pair, and evaluate that fixed intervention on held-out instances. This requires adapting methods that natively construct or retrieve from multi-skill libraries, such as SkillX and EvoSkill, into the same single-skill interface used by SkillGen. We emphasize that this controlled adaptation is not intended to measure the full native deployment potential of those systems under all possible library sizes, retrieval policies, or routing strategies. Instead, it supports a like-for-like comparison of skill synthesis quality when the deployed artifact must be one fixed skill.

这一设计也减少评估不稳定性与选择偏差。如果允许技能库方法在测试时选择不同技能，留出集性能就会将技能构建与技能库规模、检索评分、上下文预算分配、路由策略及随机技能选择等额外设计选择混为一谈。这些选择本身很重要，但引入了并非所有方法共享的额外自由度，可能使比较评估不够稳定（甚至不公平）。因此，应将所得比较理解为每个基线的受控单技能适配，而不是声称适配基线穷尽了其原生多技能能力。所有复现基线均适配到这一共享单技能评估接口：每种方法为每个基准—模型对输出一个 Markdown 格式技能，再由共享配对执行框架注入并评估。基础智能体模型用于任务执行，GPT-5.4-Mini 用于辅助提取、合并、提议和判断步骤。This design also reduces evaluation instability and selection bias. If library-based methods were allowed to select different skills at test time, held-out performance would conflate skill construction with additional design choices such as library size, retrieval scoring, context-budget allocation, routing policy, and stochastic skill selection. Those choices are important in their own right, but they introduce extra degrees of freedom that are not shared by all methods and can make a comparative evaluation less stable (and potentially unfair). The resulting comparison should therefore be interpreted as a controlled single-skill adaptation of each baseline, rather than as a claim that the adapted baselines exhaust their native multi-skill capabilities. All reproduced baselines are adapted to this shared single-skill evaluation interface: each method emits one Markdown-formatted skill per benchmark–model pair, which is then injected and evaluated by the shared paired rollout harness. The base agent model is used for task rollouts, while GPT-5.4-Mini is used for auxiliary extraction, merging, proposal, and judging steps.

无工具比较协议。No-tool comparison protocol.

在技能生成基线比较中，我们只采用受评技能不依赖外部工具、生成的辅助脚本或参考资源加载的基准设置。为确保同等条件比较，这些运行禁用 SkillGen 的可选脚本与参考资料组成部分：包括 SkillGen 在内的所有方法仅输出一个 Markdown 格式自然语言技能，即 s=(u,a,∅,∅)。任何方法均不得提供可执行辅助函数、生成工具、检索文档或 skill_load_reference 调用。全部技能通过相同提示词槽位注入，并使用相同的配对执行框架评估。因此，比较隔离出的是合成自然语言技能的质量，而非工具可用性的差异。For the skill-generation baseline comparison, we use only benchmark settings in which the evaluated skill does not rely on external tools, generated helper scripts, or reference-resource loading. To ensure a like-for-like comparison, SkillGen’s optional script and reference components are disabled in these runs: every method, including SkillGen, emits a single Markdown-formatted natural-language skill, i.e., s=(u,a,∅,∅). No method is allowed to provide executable helper functions, generated tools, retrieval documents, or calls to skill_load_reference. All skills are injected through the same prompt slot and evaluated with the same paired rollout harness. Thus, the comparison isolates the quality of the synthesized natural-language skill rather than differences in tool availability.

C.9 失败分析C.9 Failure Analysis

我们对存档的基准摘要和各模型技能分析报告进行定性检查，以补充第 4 节的汇总增益。我们不罗列孤立案例，而是提炼出技能增强何时仍会失败的四项反复出现的发现。We complement the aggregate gains in Section 4 with a qualitative inspection of the archived benchmark summaries and per-model skill-analysis reports. Rather than listing isolated examples, we distill four recurring findings about when skill augmentation still fails.

验证门控显著减少危害，但被接受的技能仍可能在留出实例上退化。The verification gate substantially reduces harm, but accepted skills can still regress on held-out instances.

最清晰的证据来自被拒绝和被接受的负面技能之间的对比。在 LiveCodeBench 上，被拒绝的技能本会使 Qwen-2.5-7B 从 25.33% 降至 16.00%，使 Gemma-4-26B 从 83.33% 降至 80.67%；因此这些单元在门控后报告零变化。Mind2Web 和 PubMedQA 也出现类似被拒绝的退化。但筛选并不完美。在 ALFWorld OOD 上，Llama-3.1-8B 的一个被接受技能仍将准确率从 67.45% 降至 65.10%，产生 51 次修复却有 57 次退化；在 ChemLLMBench 产率预测上，Mistral-Nemo 从 43.33% 降至 20.00%，仅有三次修复却有十次退化。这里的失败模式是过度泛化：在验证子集上看似有益的技能，仍可能扰乱最终划分上正确的基线行为。The clearest evidence is the contrast between rejected and accepted negative skills. In LiveCodeBench, rejected skills would have reduced Qwen-2.5-7B from 25.33% to 16.00% and Gemma-4-26B from 83.33% to 80.67%; these cells are therefore reported as zero-delta after gating. Similar rejected regressions appear in Mind2Web and PubMedQA. However, filtering is not perfect. On ALFWorld OOD, an accepted skill for Llama-3.1-8B still lowers accuracy from 67.45% to 65.10%, with 51 repairs but 57 regressions, and on ChemLLMBench yield prediction Mistral-Nemo drops from 43.33% to 20.00%, with only three repairs against ten regressions. The failure mode here is overgeneralization: a skill that looks beneficial on the verification subset can still perturb correct baseline behavior on the final split.

在交互环境中，主要残余错误是流程执行不完整，而非局部动作选择。In interactive environments, the dominant residual error is incomplete procedure execution rather than local action selection.

ALFWorld 和 ScienceWorld 均呈现这一模式。对于 ALFWorld 上的 Llama-3.1-8B，训练期分析记录了全部失败，最大簇含 65 个案例，被标记为“依赖规划不完整”。这些轨迹通常从第一个看似合理的子目标开始，却遗漏后续前提，例如检查前先开灯，或运输前先使用中间容器。ScienceWorld 在实验流程层面呈现相同现象。对于 Gemma-4-26B，分析中的 150 个构建实例有 110 个失败，较大簇分别标记为“未落实到环境的动作规划”（25）、“任务序列规划不完整”（20）和“从目标到动作的规划不完整”（19）。在两个基准上，智能体通常能够识别任务主题，却无法维持完成任务所需的完整有序流程。Both ALFWorld and ScienceWorld exhibit this pattern. For Llama-3.1-8B on ALFWorld, the training-time analysis records all failures, and the largest cluster, with 65 cases, is labeled incomplete dependency planning. These trajectories often begin the first plausible subgoal but omit a later prerequisite, such as turning on a lamp before inspection or using an intermediate receptacle before transport. ScienceWorld shows the same phenomenon at the level of experimental procedure. For Gemma-4-26B, the analysis contains 110 failures out of 150 construction instances, with large clusters labeled ungrounded action planning (25), incomplete task-sequence planning (20), and incomplete goal-to-action planning (19). In both benchmarks, the agent usually recognizes the task theme, but fails to maintain the full ordered procedure needed to finish it.

在化学任务中，失败更多源于对反应角色和决策标准的错误落实，而非事实缺失。On chemistry tasks, failures are driven less by missing facts than by incorrect grounding of reaction roles and decision criteria.

对于 ChemLLMBench 产率预测上的 Qwen-2.5-7B，训练分析报告 30 个样例中有 27 个失败，主要分为两个簇：“表面的反应可行性评估”（14）和“交叉偶联中反应角色解析错误”（13）。典型失败是模型识别出熟悉的反应族，却将底物与催化剂、碱、溶剂或添加剂混淆，随后套用通用模板预测产率，而不检查实际的亲电试剂、亲核试剂、配体／碱组合与底物适用范围。这有助于解释资源包技能为何对产率预测特别有效：增益来自强制执行基于实际反应的检查流程，而不只是重述化学知识。For Qwen-2.5-7B on ChemLLMBench yield prediction, the training analysis reports 27 failures out of 30 examples, with two dominant clusters: superficial reaction-feasibility assessment (14) and reaction-role misparsing in cross-coupling (13). A typical failure is that the model recognizes a familiar reaction family, but confuses substrates with catalysts, bases, solvents, or additives, and then predicts yield from a generic template rather than checking the actual electrophile, nucleophile, ligand/base combination, and substrate scope. This helps explain why resource-bundle skills are especially effective on yield prediction: the gain comes from enforcing a grounded checking procedure, not from merely restating chemical knowledge.

在代码生成任务中，技能增强无法完全弥补全局问题结构的缺失。On code-generation tasks, skill augmentation cannot fully compensate for missing global problem structure.

Qwen-2.5-7B 在 LiveCodeBench 上的失败主要来自上游推理错误，而非表层实现错误。训练分析报告 150 道题中有 113 个失败，主要簇标记为“算法建模不完整”（19）、“算法实现不完整”（14）和“结构映射失败”（6）。典型轨迹会在需要不变量或变换时进行暴力搜索，在需要动态规划时采用局部贪心启发式，或只推导部分解法就输出截断代码。这说明通用技能可以规范反复出现的推理习惯，但对模型从一开始就没有识别出正确组合结构的案例，无法可靠补救。LiveCodeBench failures for Qwen-2.5-7B are dominated by upstream reasoning errors rather than surface-level implementation mistakes. The training analysis reports 113 failures out of 150 problems, with major clusters labeled incomplete algorithmic modeling (19), incomplete algorithm realization (14), and structure-mapping failure (6). Typical trajectories either pursue brute-force search where an invariant or transformation is required, apply a local greedy heuristic where dynamic programming is needed, or emit truncated code after only partially deriving the solution. This suggests that a general skill can regularize recurring reasoning habits, but it cannot reliably rescue cases where the model never identifies the right combinatorial structure in the first place.

附录 D 更广泛的影响Appendix D Broader Impacts

SkillGen 旨在无需重新训练的情况下，使 LLM 智能体更可靠、更易适配，从而可能减少构建任务特定技能所需的人工投入，并通过人类可读的技能产物使流程知识更易检查。这可能有益于科学、编程、网页和工具使用工作流，因为可复用指导与验证能够提高一致性。同时，任何提升智能体性能的方法，也可能提升被用于有害或非预期目的的智能体；生成技能可能过度泛化，在未见案例上引入退化，或在错误工具使用具有现实后果的领域放大错误。当技能部署于开放式环境、安全敏感应用或涉及外部工具和资源的工作流时，这些风险尤其突出。SkillGen 的配对验证通过在构建期揭示退化，对这些危害提供部分检查。然而，检查受限于受评任务分布，因此部署前应结合应用特定的安全评估、对生成技能的人工审查、访问控制和持续监测。SkillGen aims to make LLM agents more reliable and easier to adapt without retraining, which could reduce the manual effort required to build task-specific agent skills and make procedural knowledge more inspectable through human-readable skill artifacts. This may benefit scientific, coding, web, and tool-use workflows where reusable guidance and verification can improve consistency. At the same time, any method that improves agent performance can also improve agents used for harmful or unintended purposes, and generated skills may overgeneralize, introduce regressions on unseen cases, or amplify mistakes in domains where incorrect tool use has real consequences. The risks are especially relevant when skills are deployed in open-ended environments, safety-sensitive applications, or workflows involving external tools and resources. SkillGen’s paired verification provides a partial check against these harms by making regressions visible during construction. However, these checks are limited to the evaluated task distribution, so they should be paired with application-specific safety evaluation, human review of generated skills, access controls, and ongoing monitoring before deployment.
