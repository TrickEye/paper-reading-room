摘要Abstract

智能体、领域专用推理等大语言模型（LLM）应用，越来越依赖上下文适应：通过在输入中加入指令、策略或证据来改进表现，而非更新模型权重。以往方法提升了可用性，但常受两类问题困扰：一是简洁偏好，为追求简短摘要而丢失领域洞见；二是上下文坍塌，反复重写使细节随时间流失。我们提出 ACE（Agentic Context Engineering，智能体上下文工程）框架，将上下文视为不断演化的策略手册，通过生成、反思与整理这一模块化流程，积累、提炼并组织策略。ACE 采用结构化的增量更新来防止坍塌，在保留详细知识的同时，适配长上下文模型。在智能体和领域专用基准上，ACE 同时优化离线上下文（例如系统提示词）和在线上下文（例如智能体记忆），持续超越强基线：智能体任务提升 10.6%，金融任务提升 8.6%，并显著降低适应延迟和轨迹采样成本。值得注意的是，ACE 无需标注监督，仅利用自然产生的执行反馈，也能有效适应。在 AppWorld 排行榜上，尽管采用更小的开源模型，ACE 的总体平均表现仍与排名第一的生产级智能体相当，并在更困难的 test-challenge 测试集上超过它。这些结果表明，内容全面、持续演化的上下文，能够以较低开销支撑可扩展、高效且能自我改进的 LLM 系统。Large language model (LLM) applications such as agents and domain-specific reasoning increasingly rely on context adaptation: modifying inputs with instructions, strategies, or evidence, rather than weight updates. Prior approaches improve usability but often suffer from brevity bias, which drops domain insights for concise summaries, and from context collapse, where iterative rewriting erodes details over time. We introduce ACE (Agentic Context Engineering), a framework that treats contexts as evolving playbooks that accumulate, refine, and organize strategies through a modular process of generation, reflection, and curation. ACE prevents collapse with structured, incremental updates that preserve detailed knowledge and scale with long-context models. Across agent and domain-specific benchmarks, ACE optimizes contexts both offline (e.g., system prompts) and online (e.g., agent memory), consistently outperforming strong baselines: +10.6% on agents and +8.6% on finance, while significantly reducing adaptation latency and rollout cost. Notably, ACE could adapt effectively without labeled supervision and instead by leveraging natural execution feedback. On the AppWorld leaderboard, ACE matches the top-ranked production-level agent on the overall average and surpasses it on the harder test-challenge split, despite using a smaller open-source model. These results show that comprehensive, evolving contexts enable scalable, efficient, and self-improving LLM systems with low overhead.

1 引言1 Introduction

基于大语言模型（LLM）的现代 AI 应用，例如 LLM 智能体（Yao et al., 2023；Yang et al., 2024）和复合 AI 系统（Zaharia et al., 2024），越来越依赖上下文适应。上下文适应不修改模型权重，而是在训练完成后，将更清晰的指令、结构化推理步骤或领域专用输入格式直接融入模型输入，以提高性能。上下文支撑着 AI 系统的许多组成部分，包括指导下游任务的系统提示词（Opsahl-Ong et al., 2024；Agrawal et al., 2025）、承载过往事实和经验的记忆（Suzgun et al., 2025；Xu et al., 2025），以及减少幻觉、补充知识的事实性证据（Asai et al., 2024）。Modern AI applications based on large language models (LLMs), such as LLM agents (Yao et al., 2023; Yang et al., 2024) and compound AI systems (Zaharia et al., 2024), increasingly depend on context adaptation. Instead of modifying model weights, context adaptation improves performance after model training by incorporating clarified instructions, structured reasoning steps, or domain-specific input formats directly into the model’s inputs. Contexts underpin many AI system components, including system prompts that guide downstream tasks (Opsahl-Ong et al., 2024; Agrawal et al., 2025), memory that carries past facts and experiences (Suzgun et al., 2025; Xu et al., 2025), and factual evidence that reduces hallucination and supplements knowledge (Asai et al., 2024).

通过上下文而非权重进行适应，具有几个关键优势。对用户和开发者而言，上下文可理解、可解释（Wei et al., 2022；Wang et al., 2023）；它允许在运行时快速纳入新知识（Lewis et al., 2020；Borgeaud et al., 2022），也可在复合系统的不同模型或模块间共享（Khot et al., 2023）。与此同时，长上下文 LLM 的进展（Peng et al., 2024），以及 KV 缓存复用等提高上下文效率的推理技术（Gim et al., 2024；Yao et al., 2025），使基于上下文的方法越来越适合实际部署。因此，上下文适应正成为构建能力强、可扩展、能自我改进的 AI 系统的核心范式。Adapting through contexts rather than weights offers several key advantages. Contexts are interpretable and explainable for users and developers (Wei et al., 2022; Wang et al., 2023), allow rapid integration of new knowledge at runtime (Lewis et al., 2020; Borgeaud et al., 2022), and can be shared across models or modules in a compound system (Khot et al., 2023). Meanwhile, advances in long-context LLMs (Peng et al., 2024) and context-efficient inference such as KV cache reuse (Gim et al., 2024; Yao et al., 2025) are making context-based approaches increasingly practical for deployment. As a result, context adaptation is emerging as a central paradigm for building capable, scalable, and self-improving AI systems.

尽管取得了这些进展，现有上下文适应方法仍有两项局限。第一是简洁偏好：许多提示词优化器优先追求简洁、适用的指令，而非全面积累知识。例如，GEPA（Agrawal et al., 2025）将简洁视为优点，但这种抽象可能遗漏实践中重要的领域启发式、工具使用指南和常见失败模式（Gao et al., 2025）。这一目标在某些场景下符合验证指标，却往往无法涵盖智能体和知识密集型应用所需的详细策略。第二是上下文坍塌：依赖 LLM 整体重写的方法，通常会随时间退化为更短、信息更少的摘要，导致性能骤降（图 2）。在交互式智能体（Trivedi et al., 2024；Patil et al., 2024；Zhang et al., 2024）、领域专用编程（Ye et al., 2023；Zhang et al., 2025a；Zhang et al., 2025b；Mang et al., 2025），以及金融或法律分析（Loukas et al., 2022；Guha et al., 2023；Wang et al., 2025a）等领域，出色表现依赖于保留详细、任务专用的知识，而非将其压缩掉。Despite this progress, existing approaches to context adaptation face two limitations. First, brevity bias: many prompt optimizers prioritize concise applicable instructions over comprehensive accumulation. For example, GEPA (Agrawal et al., 2025) highlights brevity as a strength, but such abstraction can omit domain-specific heuristics, tool-use guidelines, or common failure modes that matter in practice (Gao et al., 2025). This objective aligns with validation metrics in some settings, but often fails to capture the detailed strategies required by agents and knowledge-intensive applications. Second, context collapse: methods that rely on monolithic rewriting by an LLM often degrade into shorter, less informative summaries over time, causing sharp performance declines (Figure 2). In domains such as interactive agents (Trivedi et al., 2024; Patil et al., 2024; Zhang et al., 2024), domain-specific programming (Ye et al., 2023; Zhang et al., 2025a; Zhang et al., 2025b; Mang et al., 2025), and financial or legal analysis (Loukas et al., 2022; Guha et al., 2023; Wang et al., 2025a), strong performance depends on retaining detailed, task-specific knowledge rather than compressing it away.

随着智能体和知识密集型推理等应用对可靠性提出更高要求，近期研究开始向上下文中充分填入大量可能有用的信息（Jiang et al., 2025；Chung et al., 2025；Chen et al., 2025），长上下文 LLM 的进步为此提供了支持（Peng et al., 2024；Mao et al., 2024）。我们认为，上下文应当是一份全面、结构化的策略手册，内容详尽、覆盖广泛、富含领域洞见，而不应只是简短摘要。人类往往受益于简洁的概括；与之不同，LLM 在获得较长、详细的上下文时更有效，并能自主提取相关信息（Jiang et al., 2025；Liu et al., 2025b；Suzgun et al., 2025）。因此，应保留领域启发式和具体技巧，让模型在推理时决定哪些内容重要。As applications like agents and knowledge-intensive reasoning demand greater reliability, recent work has shifted toward saturating contexts with abundant, potentially useful information (Jiang et al., 2025; Chung et al., 2025; Chen et al., 2025), enabled by advances in long-context LLMs (Peng et al., 2024; Mao et al., 2024). We argue that contexts should function not as concise summaries, but as comprehensive, structured playbooks that are detailed, inclusive, and rich with domain insights. Unlike humans, who often benefit from concise generalization, LLMs are more effective when provided with long, detailed contexts and can distill relevance autonomously (Jiang et al., 2025; Liu et al., 2025b; Suzgun et al., 2025). Thus, instead of compressing away domain-specific heuristics and tactics, contexts should preserve them, allowing the model to decide what matters during inference time.

为解决上述局限，我们提出 ACE（Agentic Context Engineering，智能体上下文工程），一个面向离线场景（例如系统提示词优化）和在线场景（例如测试时记忆适应）的全面上下文适应框架。ACE 不将上下文压缩成提炼后的摘要，而是将其视为随时间积累和组织策略、不断演化的手册。ACE 在设计上采用生成、反思和整理的模块化工作流，并依照“增长与精炼”原则进行结构化增量更新。这种设计保留详细的领域专用知识，防止上下文坍塌，并使上下文在整个适应过程中保持全面且可扩展。To address these limitations, we introduce ACE (Agentic Context Engineering), a framework for comprehensive context adaptation in both offline settings (e.g., system prompt optimization) and online settings (e.g., test-time memory adaptation). Rather than compressing contexts into distilled summaries, ACE treats them as evolving playbooks that accumulate and organize strategies over time. By design, ACE incorporates a modular workflow of generation, reflection, and curation, while adding structured, incremental updates guided by a grow-and-refine principle. This design preserves detailed, domain-specific knowledge, prevents context collapse, and yields contexts that remain comprehensive and scalable throughout adaptation.

2 背景与动机2 Background and Motivation

2.1 上下文适应2.1 Context Adaptation

上下文适应（或上下文工程）是指通过构建或修改 LLM 的输入，而非改变其权重，来改进模型行为的方法。目前最先进的方法利用自然语言反馈（Shinn et al., 2023；Yuksekgonul et al., 2025；Agrawal et al., 2025）。在这一范式中，语言模型检查当前上下文，以及执行轨迹、推理步骤或验证结果等信号，生成关于如何修改上下文的自然语言反馈；再将反馈融入上下文，实现迭代适应。代表性方法包括：Reflexion（Shinn et al., 2023），通过反思失败改善智能体规划；TextGrad（Yuksekgonul et al., 2025），通过类似梯度的文本反馈优化提示词；GEPA（Agrawal et al., 2025），基于执行轨迹迭代改进提示词，表现强劲，在某些设置中甚至超过强化学习方法；以及 Dynamic Cheatsheet（动态备忘单；原文此处引用 Krause et al., 2019），在推理期间构建外部记忆，积累以往成功和失败中的策略与经验。这些自然语言反馈方法是一项重要进展，为在权重更新之外改进 LLM 系统提供了灵活且可解释的信号。Context adaptation (or context engineering) refers to methods that improve model behavior by constructing or modifying inputs to an LLM, rather than altering its weights. The current state of the art leverages natural language feedback (Shinn et al., 2023; Yuksekgonul et al., 2025; Agrawal et al., 2025). In this paradigm, a language model inspects the current context along with signals such as execution traces, reasoning steps, or validation results, and generates natural language feedback on how the context should be revised. This feedback is then incorporated into the context, enabling iterative adaptation. Representative methods include Reflexion (Shinn et al., 2023), which reflects on failures to improve agent planning; TextGrad (Yuksekgonul et al., 2025), which optimizes prompts via gradient-like textual feedback; GEPA (Agrawal et al., 2025), which refines prompts iteratively based on execution traces and achieves strong performance, even surpassing reinforcement learning approaches in some settings; and Dynamic Cheatsheet (Krause et al., 2019), which constructs an external memory that accumulates strategies and lessons from past successes and failures during inference. These natural language feedback methods represent a major advance, offering flexible and interpretable signals for improving LLM systems beyond weight updates.

2.2 现有上下文适应方法的局限2.2 Limitations of Existing Context Adaptation Methods

简洁偏好Brevity Bias

上下文适应方法反复出现的一个局限是简洁偏好：优化过程倾向于收敛到简短、通用的提示词。Gao 等人（Gao et al., 2025）在用于测试生成的提示词优化中记录了这一现象：迭代方法反复产生几乎相同的指令（例如“创建单元测试，确保各方法按预期运行”），牺牲了多样性，也遗漏了领域专用细节。这种收敛不仅缩小搜索空间，还会使重复错误跨迭代传播，因为优化后的提示词往往继承初始提示词的同类缺陷。更广泛地说，这种偏好会损害多步智能体、程序合成和知识密集型推理等领域的表现；这些领域需要详细、富含上下文的指导，成功的关键在于积累任务专用洞见，而非压缩它们。A recurring limitation of context adaptation methods is brevity bias: the tendency of optimization to collapse toward short, generic prompts. Gao et al. (Gao et al., 2025) document this effect in prompt optimization for test generation, where iterative methods repeatedly produced near-identical instructions (e.g.,, “Create unit tests to ensure methods behave as expected”), sacrificing diversity and omitting domain-specific detail. This convergence not only narrows the search space but also propagates recurring errors across iterations, since optimized prompts often inherit the same faults as their seeds. More broadly, such bias undermines performance in domains that demand detailed, context-rich guidance—such as multi-step agents, program synthesis, or knowledge-intensive reasoning—where success hinges on accumulating rather than compressing task-specific insights.

上下文坍塌Context Collapse

在 AppWorld 基准（Trivedi et al., 2024）的案例研究中，我们观察到一种称为上下文坍塌的现象：当 LLM 被要求在每个适应步骤完全重写已积累的上下文时，就可能发生这种问题。随着上下文变长，模型倾向于将其压缩成短得多、信息更少的摘要，导致信息大量丢失。例如，在第 60 步，上下文包含 18,282 个 token，准确率为 66.7；但紧接着的下一步，它就坍塌为仅 122 个 token，准确率降至 57.1，甚至低于不做适应时 63.7 的基线准确率。虽然我们借助 Dynamic Cheatsheet（Suzgun et al., 2025）展示这一问题，但它并非该方法独有，而是反映了使用 LLM 端到端重写上下文的根本风险：积累的知识可能突然被抹除，而非得到保留。In a case study on the AppWorld benchmark (Trivedi et al., 2024), we observe a phenomenon we call context collapse, which arises when an LLM is tasked with fully rewriting the accumulated context at each adaptation step. As the context grows large, the model tends to compress it into much shorter, less informative summaries, causing a dramatic loss of information. For instance, at step 60 the context contained 18,282 tokens and achieved an accuracy of 66.7, but at the very next step it collapsed to just 122 tokens, with accuracy dropping to 57.1—worse than the baseline accuracy of 63.7 without adaptation. While we highlight this through Dynamic Cheatsheet (Suzgun et al., 2025), the issue is not specific to that method; rather, it reflects a fundamental risk of end-to-end context rewriting with LLMs, where accumulated knowledge can be abruptly erased instead of preserved.

3 智能体上下文工程（ACE）3 Agentic Context Engineering (ACE)

我们提出 ACE（Agentic Context Engineering，智能体上下文工程），一个在离线场景（例如系统提示词优化）和在线场景（例如测试时记忆适应）中实现可扩展、高效上下文适应的框架。ACE 不把知识浓缩成简短摘要或静态指令，而是将上下文视为不断演化的手册，随时间持续积累、提炼并组织策略。受 Dynamic Cheatsheet（Suzgun et al., 2025）的智能体式设计启发，ACE 在三个角色之间引入结构化分工（图 4）：生成器（Generator）产生推理轨迹；反思器（Reflector）从成功与错误中提炼具体洞见；整理器（Curator）将这些洞见整合为结构化的上下文更新。这与人类通过尝试、反思和巩固来学习的方式相呼应，同时避免了由单一模型承担全部职责而形成的瓶颈。We present ACE (Agentic Context Engineering), a framework for scalable and efficient context adaptation in both offline (e.g., system prompt optimization) and online (e.g., test-time memory adaptation) scenarios. Instead of condensing knowledge into terse summaries or static instructions, ACE treats contexts as evolving playbooks that continuously accumulate, refine, and organize strategies over time. Inspired by the agentic design of Dynamic Cheatsheet (Suzgun et al., 2025), ACE introduces a structured division of labor across three roles (Figure 4): the Generator, which produces reasoning trajectories; the Reflector, which distills concrete insights from successes and errors; and the Curator, which integrates these insights into structured context updates. This mirrors how humans learn: experimenting, reflecting, and consolidating, while avoiding the bottleneck of overloading a single model with all responsibilities.

为解决 §2.2 所述既有方法的局限，尤其是简洁偏好和上下文坍塌，ACE 提出三项关键创新：（1）专门的反思器，将评估和洞见提取与整理工作分离，提高上下文质量及下游性能（§4.6）；（2）增量式差量更新（§3.1），用局部编辑取代昂贵的整体重写，同时降低延迟和计算成本（§4.7）；（3）增长与精炼机制（§3.2），在上下文稳步扩张和冗余控制之间取得平衡。To address the limitations of prior methods discussed in §2.2 (notably brevity bias and context collapse) ACE introduces three key innovations: (1) a dedicated Reflector that separates evaluation and insight extraction from curation, improving context quality and downstream performance (§4.6); (2) incremental delta updates (§3.1) that replace costly monolithic rewrites with localized edits, reducing both latency and compute cost (§4.7); and (3) a grow-and-refine mechanism (§3.2) that balances steady context expansion with redundancy control.

如图 4 所示，工作流首先由生成器针对新查询产生推理轨迹，呈现有效策略与反复出现的陷阱。反思器审视这些轨迹并提取经验，也可通过多轮迭代进一步提炼。整理器随后将经验综合成紧凑的差量条目，再由轻量级、非 LLM 的逻辑，以确定性的方式合并到现有上下文中。由于更新是逐条且局部的，可以并行合并多个差量，实现大规模批量适应。ACE 还支持多轮次适应，反复访问同一批查询，逐步增强上下文。As shown in Figure 4, the workflow begins with the Generator producing reasoning trajectories for new queries, which surface both effective strategies and recurring pitfalls. The Reflector critiques these traces to extract lessons, optionally refining them across multiple iterations. The Curator then synthesizes these lessons into compact delta entries, which are merged deterministically into the existing context by lightweight, non-LLM logic. Because updates are itemized and localized, multiple deltas can be merged in parallel, enabling batched adaptation at scale. ACE further supports multi-epoch adaptation, where the same queries are revisited to progressively strengthen the context.

3.1 增量式差量更新3.1 Incremental Delta Updates

ACE 的核心设计原则，是将上下文表示为一组结构化、条目化的要点，而非单个整体提示词。“要点”的概念类似于 Dynamic Cheatsheet（Suzgun et al., 2025）和 A-MEM（Xu et al., 2025）等 LLM 记忆框架中的记忆条目，并在此基础上扩展，包含：（1）元数据，包括唯一标识符，以及记录条目被标为有益或有害次数的计数器；（2）内容，表达可复用策略、领域概念或常见失败模式等一个小单元。在解决新问题时，生成器会指出哪些要点有帮助、哪些产生误导，以此提供反馈，引导反思器提出纠正性更新。A core design principle of ACE is to represent context as a collection of structured, itemized bullets, rather than a single monolithic prompt. The concept of a bullet is similar to the concept of a memory entry in LLM memory frameworks like Dynamic Cheatsheet (Suzgun et al., 2025) and A-MEM (Xu et al., 2025), but builds on top of that and consists of (1) metadata, including a unique identifier and counters tracking how often it was marked helpful or harmful; and (2) content, capturing a small unit such as a reusable strategy, domain concept, or common failure mode. When solving new problems, the Generator highlights which bullets were useful or misleading, providing feedback that guides the Reflector in proposing corrective updates.

这种条目化设计带来三项性质：（1）局部性，只更新相关要点；（2）细粒度检索，生成器可聚焦于最相关的知识；（3）增量适应，支持推理期间高效合并、裁剪和去重。This itemized design enables three properties: (1) localization, so only the relevant bullets are updated; (2) fine-grained retrieval, so the Generator can focus on the most pertinent knowledge; and (3) incremental adaptation, allowing efficient merging, pruning, and de-duplication during inference.

ACE 不完整重新生成上下文，而是增量生成紧凑的差量上下文：由反思器提炼、整理器整合的一小组候选要点。这既避免了完整重写的计算开销和延迟，又确保既有知识得到保留、新洞见持续加入。随着上下文增长，该方法为长时间跨度或领域知识密集型应用提供所需的可扩展性。Rather than regenerating contexts in full, ACE incrementally produces compact delta contexts: small sets of candidate bullets distilled by the Reflector and integrated by the Curator. This avoids the computational cost and latency of full rewrites, while ensuring that past knowledge is preserved and new insights are steadily appended. As contexts grow, this approach provides the scalability needed for long-horizon or domain-intensive applications.

3.2 增长与精炼3.2 Grow-and-Refine

除了增量增长，ACE 还通过定期或惰性精炼，确保上下文保持紧凑、相关。在增长与精炼过程中，带新标识符的要点会被追加，既有要点则原位更新（例如增加计数器）。随后，去重步骤利用语义嵌入比较要点，裁剪冗余内容。根据应用对延迟和准确率的要求，精炼可以主动执行（每次差量更新后），也可以惰性执行（仅在超出上下文窗口时）。Beyond incremental growth, ACE ensures that contexts remain compact and relevant through periodic or lazy refinement. In grow-and-refine, bullets with new identifiers are appended, while existing bullets are updated in place (e.g., incrementing counters). A de-duplication step then prunes redundancy by comparing bullets via semantic embeddings. This refinement can be performed proactively (after each delta) or lazily (only when the context window is exceeded), depending on application requirements for latency and accuracy.

增量更新与增长精炼机制相结合，使上下文能够自适应扩展、保持可解释性，并避免整体重写可能引入的波动。Together, incremental updates and grow-and-refine maintain contexts that expand adaptively, remain interpretable, and avoid the potential variance introduced by monolithic context rewriting.

4.2 基线与方法4.2 Baselines and Methods

基础 LLMBase LLM

基础模型不做任何上下文工程，直接使用数据集作者提供的默认提示词进行评估。对于 AppWorld，我们遵循基准作者发布的官方 ReAct（Yao et al., 2023）实现，并在该框架上构建其余所有基线及方法。The base model is evaluated directly on each benchmark without any context engineering, using the default prompts provided by dataset authors. For AppWorld, we follow the official ReAct (Yao et al., 2023) implementation released by the benchmark authors, and build all other baselines and methods on top of this framework.

上下文学习（ICL）（Agarwal et al., 2024）In-Context Learning (ICL) (Agarwal et al., 2024)

ICL 在输入提示词中为模型提供任务示例（少样本或多样本），使模型无需更新权重即可推断任务格式和期望输出。若模型上下文窗口足够大，我们提供全部训练样本；否则，尽可能用示例填满窗口。ICL provides the model with task demonstrations in the input prompt (few-shot or many-shot). This allows the model to infer the task format and desired output without weight updates. We supply all training samples when they fit within the model’s context window; otherwise, we fill the window with as many demonstrations as possible.

MIPROv2（Opsahl-Ong et al., 2024）MIPROv2 (Opsahl-Ong et al., 2024)

MIPROv2 是一种广泛使用的 LLM 应用提示词优化器，通过贝叶斯优化联合优化系统指令和上下文示例。我们采用官方 DSPy 实现（DSPy），将 auto="heavy"，以尽可能提高优化效果。MIPROv2 is a popular prompt optimizer for LLM applications that works by jointly optimizing system instructions and in-context demonstrations via bayesian optimization. We use the official DSPy implementation (DSPy, ), setting auto="heavy" to maximize optimization performance.

GEPA（Agrawal et al., 2025）GEPA (Agrawal et al., 2025)

GEPA（Genetic-Pareto）是一种基于反思式提示词演化、样本效率较高的提示词优化器。它收集执行轨迹（推理、工具调用和中间输出），通过自然语言反思诊断错误、分配贡献并提出提示词更新。遗传帕累托搜索维护一组高性能提示词构成的前沿，以缓解局部最优。实验表明，GEPA 超过 GRPO 等强化学习方法和 MIPROv2 等提示词优化器，准确率最多提高 10–20%，所需轨迹采样最多减少 35 倍。我们使用官方 DSPy 实现（DSPy），设置 auto="heavy"，以尽可能提高优化效果。GEPA (Genetic-Pareto) is a sample-efficient prompt optimizer based on reflective prompt evolution. It collects execution traces (reasoning, tool calls, intermediate outputs) and applies natural-language reflection to diagnose errors, assign credit, and propose prompt updates. A genetic Pareto search maintains a frontier of high-performing prompts, mitigating local optima. Empirically, GEPA outperforms reinforcement learning methods such as GRPO and prompt optimizers like MIPROv2, achieving up to 10–20% higher accuracy with as much as 35× fewer rollouts. We use the official DSPy implementation (DSPy, ), setting auto="heavy" to maximize optimization performance.

Dynamic Cheatsheet（DC，动态备忘单）（Suzgun et al., 2025）Dynamic Cheatsheet (DC) (Suzgun et al., 2025)

DC 是一种测试时学习方法，引入可自适应的外部记忆，存储可复用策略和代码片段。它持续利用新遇到的输入和输出更新记忆，使模型积累知识并跨任务复用，通常显著优于静态提示词方法。DC 的一个关键优势是不需要真实标签：模型可以根据自己生成的内容整理记忆，因此具有很强的灵活性和广泛适用性。我们使用作者发布的官方实现（Suzgun et al.），并选择累积模式（DC-CU）。DC is a test-time learning approach that introduces an adaptive external memory of reusable strategies and code snippets. By continuously updating this memory with newly encountered inputs and outputs, DC enables models to accumulate knowledge and reuse it across tasks, often leading to substantial improvements over static prompting methods. A key advantage of DC is that it does not require ground-truth labels: the model can curate its own memory from its generations, making the method highly flexible and broadly applicable. We use the official implementation released by the authors (Suzgun et al., ) and set it to use the cumulative mode (DC-CU).

ACE（本文方法）ACE (ours)

ACE 通过智能体上下文工程框架，针对离线和在线适应优化 LLM 上下文。为保证公平，生成器、反思器和整理器使用同一个 LLM，即 DeepSeek-V3.1 的非思考模式（Liu et al., 2024a），避免较强反思器或整理器向较弱生成器转移知识，从而隔离上下文构建本身带来的收益。我们还在附录中使用其他骨干 LLM 评估 ACE，均观察到稳定增益。批大小设为 1，即每个样本构建一个差量上下文。反思器最大精炼轮数，以及离线适应的最大训练轮次，均设为 5。ACE optimizes LLM contexts for both offline and online adaptation through an agentic context engineering framework. To ensure fairness, we use the same LLM for the Generator, Reflector, and Curator (non-thinking mode of DeepSeek-V3.1 (Liu et al., 2024a)), preventing knowledge transfer from a stronger Reflector or Curator to a weaker Generator. This isolates the benefit of context construction itself. We additionally evaluate ACE with other backbone LLMs in the appendix, where we observe consistent gains. We adopt a batch size of 1 (constructing a delta context from each sample). We set the maximum number of Reflector refinement rounds and the maximum number of epoch in offline adaptation to 5.

对反思质量的稳健性Robustness to Reflection Quality

ACE 对反思质量具有稳健性：即使反思器弱得多，它仍然有效；更强的反思器只带来适度额外增益。在噪声或有害反思下，性能平缓下降，除每次迭代都施加完全对抗性更新外，仍高于基础模型。完整实验结果见附录 §A.4。ACE is robust to reflection quality: it remains effective with a much weaker Reflector and shows only modest additional gains from stronger reflectors, and it degrades gracefully under noisy/harmful reflections, staying above the base model except under fully adversarial updates every iteration. Full experiment results are in Appendix §A.4.

在广泛的合理超参数设置下，例如反思器精炼轮数、适应轮次，以及增长与精炼阈值，ACE 的收益都很稳定：性能变化较小，且始终高于对应基线。完整讨论和详细结果见附录 §A.6。ACE’s gains are stable across a wide range of reasonable hyperparameter settings (e.g., Reflector refinement rounds, number of adaptation epochs, and grow-and-refine thresholds): performance changes are modest, and ACE consistently remains above the corresponding baselines. Full discussion and detailed results are reported in Appendix §A.6.

4.7 成本与速度分析4.7 Cost and Speed Analysis

由于支持增量式“差量”上下文更新，以及不依赖 LLM 的上下文合并和去重，ACE 在降低适应成本（按轨迹采样数量，或 token 输入／生成的货币成本衡量）和延迟方面具有明显优势。Due to its support for incremental, “delta” context updates and non-LLM-based context merging and de-duplication, ACE demonstrates particular advantages in reducing the cost (in terms of the number of rollouts or the amount of dollar cost for token ingestion/generation) and latency of adaptation.

例如，在 AppWorld 的离线适应中，相比 GEPA，ACE 的适应延迟降低 82.3%，轨迹采样数量减少 75.1%（表 4(a)）。在 FiNER 的在线适应中，相比 DC，ACE 的适应延迟降低 91.5%，token 输入／生成的货币成本降低 83.6%（表 4(b)）。As examples, on the offline adaptation of AppWorld, ACE achieves 82.3% reduction in adaptation latency and 75.1% reduction in the number of rollouts as compared to GEPA (Table 4(a)). On the online adaptation of FiNER, ACE achieves 91.5% reduction in adaptation latency and 83.6% reduction in token dollar cost for token ingestion/generation as compared to DC (Table 4(b)).

细粒度成本分析Fine-Grained Cost Analysis

我们对 ACE 和代表性基线 GEPA 进行细粒度成本分析。在 AppWorld 上，ACE 的离线适应成本显著更低，相比 GEPA，输入／输出 token 用量分别减少 80.8%／83.6%：ACE 避免了 GEPA 的提示词验证循环，并以局部差量更新替代反复的完整重写。评估时，ACE 可能因策略手册更丰富而使用更多原始输入 token，但这并不一定意味着更高的实际推理计费，因为上下文有很大一部分可通过 KV 缓存复用；下一段将量化这一影响。完整结果及两种方法按组件拆分的 token 用量见附录 §A.3。We conduct a fine-grained cost analysis of ACE and GEPA (as a representative baseline). On AppWorld, ACE is substantially cheaper during offline adaptation, reducing input/output token usage by 80.8%/83.6% vs. GEPA: ACE avoids GEPA’s prompt-validation loop and replaces repeated full rewrites with localized delta updates. At evaluation time, while ACE may use more raw input tokens due to a richer playbook, this does not necessarily translate to higher billed serving cost because a large fraction of the context is reused by KV caching; we quantify this effect in the next paragraph. Full results, including a component-wise token breakdown for both methods, are in Appendix §A.3.

KV 缓存复用：更长上下文 ≠ 更高推理服务成本KV Cache Reuse: Longer Context ≠ Higher Serving Cost

尽管 ACE 产生的上下文比 GEPA 等方法更长，这并不会使推理成本或 GPU 显存用量线性增加。现代推理服务基础设施越来越多地采用 KV 缓存复用（Gim et al., 2024；Yao et al., 2025）、压缩（Liu et al., 2024c；Liu et al., 2024b）和卸载（Lee et al., 2024；Li et al., 2025）技术，优化长上下文工作负载。这些机制将频繁复用的上下文片段缓存在本地或远端，避免重复、昂贵的预填充操作。机器学习系统的持续进步表明，处理长上下文的摊销成本很可能下降，使 ACE 这类上下文丰富的方法越来越适合部署。我们使用 OpenAI API（GPT-5.1）进行提示词缓存研究，发现 ACE 具有很高的缓存复用率：在评估阶段，91.8% 的输入 token 由缓存提供，相对于直接按原始上下文 token 计数，输入 token 的实际计费成本降低 82.6%。Although ACE produces longer contexts than methods such as GEPA, this does not translate to linearly higher inference cost or GPU memory usage. Modern serving infrastructures are increasingly optimized for long-context workloads through techniques such as the reuse (Gim et al., 2024; Yao et al., 2025), compression (Liu et al., 2024c; Liu et al., 2024b), and offload (Lee et al., 2024; Li et al., 2025) of KV cache. These mechanisms allow frequently reused context segments to be cached locally or remotely, avoiding repetitive and expensive prefill operations. Ongoing advances in ML systems suggest that the amortized cost of handling long contexts is likely to decrease, making context-rich approaches like ACE increasingly practical in deployment. In our prompt-caching study with the OpenAI API (GPT-5.1), we find that ACE achieves high cache reuse: 91.8% of input tokens are served from cache during evaluation stage, which reduces billed input-token cost by 82.6% relative to counting raw context tokens.

5 讨论5 Discussion

对在线学习与持续学习的启示Implications for Online and Continual Learning

在线学习与持续学习是机器学习的重要研究方向，用于解决分布漂移（Koh et al., 2021；Gulrajani and Lopez-Paz, 2021）和训练数据有限（Pan and Yang, 2010；Hutchinson et al., 2017；Zhuang et al., 2019）等问题。ACE 为常规模型微调提供了灵活、高效的替代方案，因为调整上下文通常比更新模型权重更便宜（Brown et al., 2020；Lester et al., 2021；Li and Liang, 2021；Hu et al., 2022）。此外，由于上下文对人类可解释，ACE 支持选择性遗忘（Cao and Yang, 2015；Bourtoule et al., 2021；Liu et al., 2025a），无论是出于隐私或法律约束（2016；2018），还是领域专家发现了过时或错误信息。这些都是值得进一步研究的方向，ACE 有望在推动持续且负责任的学习方面发挥核心作用。Online and continual learning are key research directions in machine learning for addressing issues like distribution shifts (Koh et al., 2021; Gulrajani and Lopez-Paz, 2021) and limited training data (Pan and Yang, 2010; Hutchinson et al., 2017; Zhuang et al., 2019). ACE offers a flexible and efficient alternative to conventional model fine-tuning, as adapting contexts is generally cheaper than updating model weights (Brown et al., 2020; Lester et al., 2021; Li and Liang, 2021; Hu et al., 2022). Moreover, because contexts are human-interpretable, ACE enables selective unlearning (Cao and Yang, 2015; Bourtoule et al., 2021; Liu et al., 2025a), whether due to privacy or legal constraints (, 2016; , 2018), or when outdated or incorrect information is identified by domain experts. These are promising directions for future work, where ACE could play a central role in advancing continuous and responsible learning.

局限与挑战Limitations and Challenges

ACE 的一个局限是依赖具备一定能力的反思器：若反思器无法从生成轨迹或结果中提取有意义的洞见，构建的上下文可能充满噪声，甚至有害。在没有模型能提取有效洞见的领域任务中，得到的上下文自然也缺少这些洞见。这种依赖类似于 Dynamic Cheatsheet（Suzgun et al., 2025），其适应质量取决于底层模型整理记忆的能力。我们也指出，并非所有应用都需要丰富或详细的上下文。HotPotQA（Yang et al., 2018）等任务，通常更受益于简洁、高层次的指令，例如如何检索并综合证据，而非长上下文。类似地，Game of 24（Suzgun et al., 2025）等策略固定的游戏，可能只需一条可复用规则，更多上下文反而冗余。总体而言，ACE 最适合需要详细领域知识、复杂工具使用或特定环境策略的场景；这些内容超出模型权重中已有知识或简单系统指令的覆盖范围。A limitation of ACE is its reliance on a reasonably strong Reflector: if the Reflector fails to extract meaningful insights from generated traces or outcomes, the constructed context may become noisy or even harmful. In domain-specific tasks where no model can extract useful insights, the resulting context will naturally lack them. This dependency is similar to Dynamic Cheatsheet (Suzgun et al., 2025), where the quality of adaptation hinges on the underlying model’s ability to curate memory. We also note that not all applications require rich or detailed contexts. Tasks like HotPotQA (Yang et al., 2018) often benefit more from concise, high-level instructions (e.g., how to retrieve and synthesize evidence) than from long contexts. Similarly, games with fixed strategies such as Game of 24 (Suzgun et al., 2025) may only need a single reusable rule, rendering additional context redundant. Overall, ACE is most beneficial in settings that demand detailed domain knowledge, complex tool use, or environment-specific strategies that go beyond what is already embedded in model weights or simple system instructions.

A.3 细粒度成本分析A.3 Fine-Grained Cost Analysis

我们以 AppWorld 为代表性应用，在离线适应设置下，分别对 ACE 和 GEPA 的适应及评估阶段进行细粒度成本分析。ACE 使用 1 个训练轮次、1 轮反思器精炼进行离线适应。增加训练轮次或精炼轮数会提高成本，但下述定性趋势应保持不变：ACE 避免昂贵的验证阶段重复评估，并进行局部更新，而非反复完整重写。GEPA 使用官方 DSPy 实现（DSPy），设置 auto="heavy"，以尽可能增强优化力度。We perform a fine-grained cost analysis of ACE and GEPA for both the adaptation and evaluation stages (offline adaptation setting), using AppWorld as a representative application. For ACE, we run offline adaptation with 1 epoch and 1 reflector refinement round. While increasing the number of epochs or refinement rounds will increase cost, the qualitative trends below should remain: ACE avoids expensive validation-time re-evaluation and performs localized updates rather than repeated full rewrites. For GEPA, we use the official DSPy implementation (DSPy, ) with auto="heavy" to maximize optimization strength.

适应阶段Adaptation Stage

在整个适应阶段（表 12、表 13），ACE 相比 GEPA 的输入 token 用量减少 80.8%（204.1M → 39.3M），输出 token 用量减少 83.6%（1.87M → 0.31M）。这一差距主要来自：（1）GEPA 的提示词验证循环，在留出的验证集（57 个查询）上反复评估候选提示词，产生大量额外 LLM 调用及验证 token；（2）ACE 的增量上下文更新，用生成器—反思器—整理器的局部更新替代完整提示词重写。Across adaptation (Table 12 and Table 13), ACE reduces input-token usage by 80.8% relative to GEPA (204.1M → 39.3M) and output-token usage by 83.6% (1.87M → 0.31M). This gap is primarily driven by (1) GEPA’s prompt-validation loop, which repeatedly evaluates candidate prompts on a held-out validation set (57 queries), incurring substantial additional LLM calls and validation tokens, and (2) ACE’s incremental context updates, which replace full prompt rewrites with localized Generator-Reflector-Curator updates.

评估阶段Evaluation Stage

在评估阶段（表 14、表 15），由于策略手册更丰富、可操作性更强，ACE 每个查询使用的原始输入 token 多于 GEPA。但二者输出 token 用量接近（115.0 对 101.8），轨迹采样数量也相当。此外，现代提示词／KV 缓存基础设施能够大幅摊薄额外输入 token 的成本：使用 OpenAI 默认提示词缓存时，ACE 的 91.8% 输入 token 由缓存提供，输入 token 的实际计费成本降低 82.6%（见 §4.7）。At evaluation time (Table 14 and Table 15), ACE uses more raw input tokens per query than GEPA due to its richer, more actionable playbook. However, output-token usage is similar (115.0 vs. 101.8), and the number of rollouts is comparable across methods. Moreover, under modern prompt/KV-caching infrastructures, the additional input tokens can be largely amortized: using OpenAI’s default prompt caching, 91.8% of ACE’s input tokens are served from cache, resulting in an 82.6% reduction in billed input-token cost (see §4.7).

使用较弱的反思器模型Using Weaker Reflector Models

为测试 ACE 是否需要强反思器，我们在三个能力差异较大的模型之间切换反思器：GPT-OSS-120B、DeepSeek-V3.1-671B 和 GPT-5.1（表 16）。在所有选择下，ACE 均持续优于基础 LLM，即使反思器弱得多也是如此。虽然更强反思器带来更大增益，但该方法在广泛的反思器能力范围内都有效。To test whether ACE requires a strong reflector, we vary the Reflector across three models with substantially different capability: GPT-OSS-120B, DeepSeek-V3.1-671B, and GPT-5.1 (Table 16). Across all choices, ACE consistently improves over the base LLM, including when the Reflector is much weaker. While stronger reflectors yield larger gains, the method remains effective across a wide range of reflector strengths.

对噪声或有害反思反馈的稳健性Robustness to Noisy or Harmful Reflector Feedback

我们进一步通过注入对抗性或相互冲突的要点，对主动有害的反思器输出进行压力测试：每隔 X 个适应步骤调用一次“有害”反思器，并明确指示它注入有害反思；X 越大，污染越不频繁（表 17）。ACE 对中等噪声水平具有稳健性：随着污染更频繁，性能逐步下降，但除每次迭代都注入有害更新这一极端情形外，始终高于基础 LLM。这表明 ACE 的更新机制能容忍反思流中的相当程度噪声，只有在刻意对抗条件下才会失效。We further stress-test ACE with actively harmful reflector outputs by injecting adversarial or conflicting bullets: we invoke a “harmful” reflector that is explicitly instructed to inject harmful reflection once every X adaptation steps, where larger X means less frequent corruption (Table 17). ACE is robust to moderate noise levels: performance degrades gradually as corruption becomes more frequent and stays above the base LLM except in the extreme case of injecting harmful updates every iteration. This suggests that ACE’s update mechanism tolerates substantial noise in the reflection stream, with failures emerging only under intentionally adversarial conditions.

结论与缓解措施Takeaway and Mitigation

ACE 对反思器质量并不高度敏感：（1）较弱反思器仍带来显著收益；（2）中等噪声或冲突更新大体可被容忍；（3）只有持续的对抗性污染才会使性能低于基础模型。实践中，ACE 的要点分析器（“增长与精炼”，§3.2）会合并并去重语义相近的要点，还可依据元数据过滤被标记为潜在有害的条目，构成抵御上下文噪声的第一道防线。额外保护措施，例如矛盾检测、提示整理器优先采用高置信度更新，或定期裁剪过时条目，都是兼容的扩展，可进一步提升策略手册的紧凑性和一致性（Zhou et al., 2024）。ACE is not highly sensitive to reflector quality: (1) weaker reflectors still provide substantial gains, (2) moderate noise or conflicting updates are largely tolerated, and (3) performance drops below the base model only under sustained adversarial corruption. In practice, ACE’s bullet-point analyzer (“grow-and-refine”; §3.2), which merges and deduplicates semantically similar bullets and can filter entries flagged as potentially harmful via metadata, serves as a first line of defense against context noise. Additional safeguards (e.g., contradiction detection, prompting the Curator to prioritize high-confidence updates, or periodic pruning of outdated entries) are compatible extensions that could further improve playbook compactness and consistency (Zhou et al., 2024).

A.5 增量上下文更新的消融实验A.5 Ablation on Incremental Context Update

本消融实验在 AppWorld 上，分别使用带和不带增量上下文更新的 ACE 进行离线上下文适应，以 DeepSeek-V3.1 在 test-normal 子集评估。结果发现，增量更新至关重要：它保留了原本会因上下文坍塌而丢失的有用信息，贡献了 ACE 增益的很大一部分。In this ablation, we run offline context adaptation on AppWorld using ACE with and without incremental context updates, and evaluate on the test-normal split with DeepSeek-V3.1. We find that incremental updates are critical: by preserving useful information that would otherwise be lost to context collapse, they account for a large share of ACE ’s gains.

A.6 超参数选择的敏感性分析A.6 Sensitivity Analysis on Hyperparameter Choice

反思迭代次数Reflection Iterations

该参数需要在两个目标之间权衡：（1）从推理轨迹中提取足够多高质量洞见；（2）避免“过度思考”引入噪声或不必要更新。经验上，5 轮能够较好平衡两者。在 AppWorld 上，1 轮不足以提取有用的策略片段，仍有明显提升空间；轮数过多（例如 10 轮）则可能降低性能。This parameter trades off (1) extracting enough high-quality insights from the inference traces and (2) avoiding “overthinking” that introduces noisy or unnecessary updates. Empirically, 5 rounds offers a good balance. On AppWorld, 1 round under-extracts useful strategy fragments and leaves clear headroom, while too many rounds (e.g., 10) can degrade performance.

去重阈值Deduplication Threshold

该参数控制新提取洞见与既有条目的合并力度。在 FiNER 上，测试范围内的性能变化很小，说明 ACE 对去重强度的适度变化具有稳健性。This controls how aggressively newly extracted insights are merged with existing entries. On FiNER, performance changes only mildly across the tested range, suggesting ACE is robust to moderate variation in dedup aggressiveness.

裁剪触发阈值（最大上下文长度）Pruning Trigger (Maximum Context Length)

该阈值决定 ACE 何时合并和裁剪较旧或效用较低的条目，以防无限增长。它需要权衡：（1）保留足够的已积累上下文，改善经验学习；（2）保持上下文紧凑，降低成本并限制噪声。在 FiNER 上，从 10K 到 100K token，性能保持稳定，说明 ACE 不需要精细调节长度阈值；裁剪主要移除过时或有害片段，同时保留核心可复用策略。This threshold determines when ACE merges and prunes older or low-utility entries to prevent unbounded growth. It balances (1) retaining enough accumulated context to improve learning from experience and (2) keeping the context compact to reduce cost and limit noise. On FiNER, performance is stable from 10K to 100K tokens, indicating ACE does not require finely tuned length thresholds; pruning mainly removes stale or harmful fragments while preserving core reusable strategies.

总体而言，ACE 对这些超参数并不高度敏感：合理选择，例如 3–5 轮反思、50–90% 的去重阈值，以及 10K–100K 的裁剪触发阈值，都能稳定取得较强表现。Overall, ACE is not highly sensitive to these hyperparameters: reasonable choices (e.g., 3-5 reflection rounds, 50-90% dedup threshold, and 10K-100K pruning triggers) consistently yield strong performance.

附录 B 扩展相关工作Appendix B Extended Related Work

B.1 智能体记忆B.1 Agent Memory

越来越多研究探索智能体如何从以往轨迹中积累经验，并利用外部记忆（通常为非参数化记忆）指导后续行动。AgentFly（Zhou et al., 2025）提出一个可扩展框架：记忆随智能体解决任务持续演化，支持跨不同环境的可扩展强化学习和长跨度推理。AWM（Agent Workflow Memory，智能体工作流记忆）（Wang et al., 2025b）从过去轨迹中归纳出可复用工作流，即结构化例程，并选择性地将其注入记忆，提高网页导航基准上的效率与泛化能力。A-MEM（Xu et al., 2025）借鉴卡片盒笔记法，提出动态组织的记忆系统：每条记忆都带有标签、关键词、上下文描述等结构化属性，并自动关联相关的既有条目；同时更新旧条目以整合新知识，实现自适应、具备上下文感知能力的检索。Agentic Plan Caching（Zhang et al., 2025c）则聚焦成本效率，从智能体轨迹中提取可复用的计划模板并缓存，以便测试时快速执行。A growing body of work explores how agents can accumulate experience from past trajectories and leverage external (often non-parametric) memory to guide future actions. AgentFly (Zhou et al., 2025) presents an extensible framework where memory evolves continuously as agents solve tasks, enabling scalable reinforcement learning and long-horizon reasoning across diverse environments. AWM (Agent Workflow Memory) (Wang et al., 2025b) induces reusable workflows, i.e., structured routines distilled from past trajectories, and selectively injects them into memory to improve efficiency and generalization in web navigation benchmarks. A-MEM (Xu et al., 2025) introduces a dynamically organized memory system inspired by the Zettelkasten method: each stored memory is annotated with structured attributes (e.g., tags, keywords, contextual descriptions) and automatically linked to relevant past entries, while existing entries are updated to integrate new knowledge, yielding adaptive and context-aware retrieval. Agentic Plan Caching (Zhang et al., 2025c) instead focuses on cost efficiency by extracting reusable plan templates from agent trajectories and caching them for fast execution at test time.

这些研究共同展示了外部记忆在提高 LLM 智能体适应性、效率和泛化能力方面的价值。本文的不同之处在于处理更广泛的上下文适应挑战：不只包括智能体记忆，还涵盖系统提示词、事实证据及其他支撑 AI 系统的输入。我们进一步指出现有适应方法的两个根本局限——简洁偏好和上下文坍塌——并说明，解决它们不仅关系到原始任务性能，也是获得稳健性、可靠性和可扩展性的关键。因此，评估不仅考察准确率，还考察成本、延迟和可扩展性。Together, these works demonstrate the value of external memory for improving adaptability, efficiency, and generalization in LLM agents. Our work differs by tackling the broader challenge of context adaptation, which spans not only agent memory but also system prompts, factual evidence, and other inputs underpinning AI systems. We further highlight two fundamental limitations of existing adaptation methods: brevity bias and context collapse; and show that addressing them is essential for robustness, reliability, and scalability beyond raw task performance. Accordingly, our evaluation considers not only accuracy but also cost, latency, and scalability.

附录 C 扩展讨论Appendix C Extended Discussions

C.1 ACE 与 GEPA 的比较C.1 ACE vs. GEPA

范围与目标。GEPA 和 ACE 都通过测试时调整上下文来改进模型或智能体行为，而非更新模型权重，但二者面向的适应形式不同。GEPA 将适应视为提示词演化：利用采样轨迹和反思反馈，迭代提出并选择更好的指令提示词，目标是在轨迹采样预算内最大化任务评估指标。ACE 针对的是长期积累并保留大量细粒度、可复用洞见才能获得良好表现的场景。对于 AppWorld 等多轮智能体，模型必须在交互过程中保留逐步操作流程和工具使用规则。对于 FiNER、Formula 等领域专用和知识密集型基准，准确率取决于保留大量具体规则、边界情况和领域概念；若将其压缩进单一指令提示词，很难不丢失细节。Scope and Objective Both GEPA and ACE improve model or agent behavior by adapting context at test time (rather than updating model weights), but they are designed for different forms of adaptation. GEPA treats adaptation as prompt evolution: it iteratively proposes and selects improved instruction prompts using rollout trajectories and reflective feedback, aiming to maximize a task evaluator under a rollout budget. ACE targets settings where performance depends on accumulating and preserving many granular, reusable insights over long horizons. For multi-turn agents (e.g., AppWorld), the model must retain step-by-step procedures and tool-use rules across an interaction. For domain-specific and knowledge-intensive benchmarks (e.g., FiNER, Formula), accuracy depends on keeping many specific rules, edge cases, and domain concepts that are difficult to compress into a single instruction prompt without losing detail.

更新机制与表示。GEPA 在演化循环中生成并选择新的提示词变体来更新上下文，每个候选都是端到端优化的完整提示词。ACE 则将上下文表示为结构化、条目化的策略手册，并应用增量式差量更新：整理器只写出新洞见，再通过简单、确定性的逻辑合并进手册。这避免了反复完整重写提示词，有助于在长时间运行中保持早期规则稳定，并支持细粒度管理，例如去重、定向精炼，以及追踪哪些条目帮助或损害准确率。Update Mechanism and Representation GEPA updates context by generating and selecting new prompt variants in an evolutionary loop, where each candidate is a full prompt optimized end-to-end. ACE instead represents context as a structured, itemized Playbook and applies incremental delta updates: the Curator writes only the new insight, and we merge it into the Playbook with simple deterministic logic. This avoids repeated full-prompt rewrites, helps keep earlier rules stable over long runs, and enables fine-grained bookkeeping (e.g., de-duplication, targeted refinement, and tracking which entries helped or harmed accuracy).

C.2 ACE 与 Dynamic Cheatsheet（DC）的比较C.2 ACE vs. Dynamic Cheatsheet (DC)

范围与目标。DC 和 ACE 都在测试时收集可复用洞见，但面向的场景不同。DC 主要在 AIME、Game-of-24 和 GPQA 等单轮推理基准上评估，其中各查询相互独立。在这种情况下，改进通常来自保存简短、可复用的启发式和可执行产物（例如代码片段），供后续问题使用。ACE 聚焦的是必须长期保留细节与高保真指导的场景。对于 AppWorld 等多轮智能体，模型必须在交互中记住逐步操作流程和工具使用规则。对于 FiNER、Formula 等领域专用和知识密集型基准，准确率依赖大量具体规则、边界情况和领域概念，而这些内容很难在不损失信息的前提下被压缩。Scope and Objective Both DC and ACE collect reusable insights at test time, but they are aimed at different settings. DC is mainly evaluated on single-turn reasoning benchmarks (e.g., AIME, Game-of-24, GPQA) where each query is independent. In this regime, improvements often come from saving short, reusable heuristics and executable artifacts (e.g., code snippets) that help on later problems. ACE focuses on settings where the details and high-fidelity guidenace need to stick around. For multi-turn agents (e.g., AppWorld), the model must remember step-by-step procedures and tool-use rules across an interaction. For domain-specific and knowledge-intensive benchmarks (e.g., FiNER, Formula), accuracy depends on keeping many specific rules, edge cases, and domain concepts, which are hard to compress without losing information.

更新机制。DC 通过整体重写备忘单更新记忆：每一步重新生成完整备忘单（DC-CU），或根据检索到的示例编写新摘要（DC-RS）。反复完整重写时，模型倾向于缩短和压缩此前内容，可能引发上下文坍塌，使有用的领域细节逐渐丢失或突然消失（§2.2）。ACE 以增量式差量更新避免完整重写。整理器只写新洞见，再通过简单、确定性的逻辑合并进结构化、条目化的策略手册。这能使早期规则在长期运行中保持稳定，也更易追踪有帮助的条目、移除重复并精炼内容。在消融实验中（§4.6），移除差量更新会使 AppWorld 表现大幅下降：test-normal 的 TGC 下降 11.7%，SGC 下降 27.8%，说明差量更新是方法的核心组成部分。Update Mechanism DC updates its memory by rewriting the cheatsheet as a whole, either by regenerating the full cheatsheet each step (DC-CU) or by writing a new summary from retrieved examples (DC-RS). With repeated full rewrites, the model tends to shorten and compress what was written before. This can cause context collapse, which means that useful domain-specific details get dropped over time or disappear suddenly (§2.2). ACE avoids full rewrites by using incremental delta updates. The Curator only writes the new insight, and we merge it into a structured and itemized Playbook with simple deterministic logic. This keeps earlier rules stable over long runs and also makes it easier to track which items helped, remove duplicates, and refine entries. In our ablations (§4.6), removing delta updates leads to a large drop on AppWorld (-11.7% TGC and -27.8% SGC on test-normal), showing that delta updates are a core part of our method.
